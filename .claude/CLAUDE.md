# Учёт времени · Битрикс24 — правила для Claude Code

## Что это за проект

Личный дашборд списанного времени по задачам Битрикс24: итог, среднее за рабочий день, график активности, список задач, доли по задачам за сегодня / неделю / месяц / год. Разработчик — Никита Мальцев. Пользовательское описание и структура папок — в `README.md`, здесь только то, чего из кода не видно.

Если решение нигде не зафиксировано — **спросить Никиту, не придумывать**.

## Окружение

- **Node.js 22 LTS** (`.nvmrc`). На Node 26 Turbopack в Next 16.2 бесконечно перезапускает воркер PostCSS/Tailwind — сотни процессов, машина виснет. В шелле Claude по умолчанию может стоять другая версия: **перед `npm run dev` / `npm run build` проверить `node -v`** и при необходимости `nvm use`.
- Вебхук Битрикс24 — в `.env.local` (`B24_WEBHOOK`, слеш в конце обязателен). Отчёт строится по пользователю, которому принадлежит вебхук.
- `next.config.mjs` → `allowedDevOrigins` с IP стенда: dev-сервер открывают с другой машины, не удалять.
- Проверка изменений: `npm test` (чистые функции, `node --test`), `npm run lint`, затем `npm run build`. UI проверяется в браузере на dev-сервере.

## REST Битрикс24 — что уже выяснено (не переоткрывать)

- **Время идущего таймера получить нельзя**: методов `task.timer.*` в REST нет, полей таймера у задачи тоже. Запись появляется только после паузы/остановки. Не пытаться «добавить текущий таймер» — это уже проверено.
- Пагинация — `b24AllPages` в `src/lib/b24.js`: первая страница обычным запросом (даёт `total`), остальные пачками через `batch`. У старых методов `task.*` внутри `batch` параметр `start` игнорируется — страница задаётся через `PARAMS[NAV_PARAMS][iNumPage]`, и **порядок параметров позиционный** (`ORDER, FILTER, SELECT, PARAMS`).
- Задачи «в работе» — два отдельных запроса (исполнитель и соисполнитель). `::SUBFILTER` с `::LOGIC OR` теряет часть задач — не «упрощать» обратно в один запрос.
- Права вебхука: `task` и `user`.
- `CREATED_DATE` приходит в ISO с часовым поясом портала; день и час берутся срезом строки, без `new Date()`, чтобы не съезжать по поясу. Начало периода (`periodStart`) считается в поясе сервера.

## Архитектура и соглашения

- **Вебхук только на сервере.** `src/lib/b24.js` импортируется только из route handlers `src/app/api/b24/**`. Клиентский код ходит в `/api/b24/*`, не в Битрикс напрямую.
- **Агрегация на сервере.** `buildReport` отдаёт готовую сводку (`totalSeconds`, `avgSeconds`, `tasks`, `days`, `hours` только для `today`, …). Новые вычисления по записям — туда же, а не на клиент. Меняешь форму сводки — обнови README.
- **Слои** (облегчённый FSD): `app → windows → widgets → entities → shared`. Импорт только вниз: entity не импортирует widget, `shared` не знает о сторе.
- **Redux.** Стор создаётся через `makeStore` в `store-provide.js`; `StoreProvider` стоит в `page.js`, а не в `layout.js`, потому что только page получает `searchParams` (период из `?period=`). Отчёт загружает **только** `widgets/contentHeader.jsx` (при загрузке, смене фильтра и по `reloadKey` — кнопка «Обновить»); остальные виджеты лишь читают `state.time`. Новый виджет не делает свой fetch.
- Периоды: на клиенте — `FILTERS` (`shared/filters.js`, числовые id), на сервере — `PERIODS` (`lib/b24.js`, slug). Добавляешь период — правь оба места.
- **Тесты** — `*.test.js` рядом с модулем, только для чистых функций (`lib/report.js`, `shared/dates.js`, `shared/format.js`, `widgets/chartBars.js`). В Node нет алиаса `@/`, поэтому такие модули либо без импортов, либо с относительными импортами с расширением (`'../shared/dates.js'`). Вычисления, которые стоит покрыть тестом, выносить в такой модуль.
- Норма дня (6ч 45м минимум, 8ч полный день) — в `shared/norm.js`.
- Стиль кода: JS/JSX без TypeScript, Tailwind 4 с цветами прямо в классах (`bg-[#fbf7f2]`), алиас `@/` → `src/`. Комментарии короткие, по-русски, про «почему».
- **Next.js 16** — см. блок выше: перед использованием API Next читать `node_modules/next/dist/docs/01-app/`.
