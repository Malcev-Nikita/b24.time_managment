# Учёт времени · Битрикс24

Личный дашборд затреканного времени по задачам Битрикс24: сколько времени списано за сегодня, неделю, месяц или с начала года — итог, среднее за рабочий день, количество рабочих дней и задач в работе, список задач с записями и временем, доли времени по задачам.

Данные берутся из REST API Битрикс24 через входящий вебхук. Вебхук живёт только на сервере (route handlers Next.js) и в браузер не попадает.

## Стек

- [Next.js 16](https://nextjs.org) (App Router, Turbopack)
- React 19
- [Redux Toolkit](https://redux-toolkit.js.org) + react-redux (стор создаётся per-request через `makeStore`)
- Tailwind CSS 4

## Требования

- **Node.js 22 LTS** (проверено на 22.20.0). На Node 26 dev-сервер не работает: воркер PostCSS/Tailwind в Turbopack (Next 16.2) падает при старте, и Turbopack бесконечно перезапускает его — за секунды появляются сотни процессов `node.exe`, память и ЦП съедаются полностью, компьютер зависает. Если стоит nvm:

  ```bash
  nvm use 22.20.0
  ```

## Запуск

1. Создайте входящий вебхук в Битрикс24: **Разработчикам → Другое → Входящий вебхук**.

   В настройке прав вебхука обязательно выдайте доступ к **задачам — `task`** (методы `task.elapseditem.getlist` и `tasks.task.list`) и **пользователям — `user`** (метод `profile`). Без права `task` отчёт вернёт ошибку доступа.

2. Положите его в `.env.local` в корне проекта (слеш в конце обязателен):

   ```
   B24_WEBHOOK=https://ваш-портал.bitrix24.ru/rest/123/xxxxxxxxxxxxxxxx/
   ```

3. Установите зависимости и запустите dev-сервер:

   ```bash
   npm install
   npm run dev
   ```

4. Откройте [http://localhost:3000](http://localhost:3000).

Отчёт строится по пользователю, которому принадлежит вебхук.

## Как устроено

```
src/
├── app/
│   ├── api/b24/          # серверные прокси к Битрикс24 (вебхук не уходит на клиент)
│   │   ├── profile/      # GET /api/b24/profile — текущий пользователь
│   │   └── time/         # GET /api/b24/time?period=today|week|month|year — агрегат
│   ├── layout.js         # шапка, футер, StoreProvider
│   └── page.js           # дашборд
├── lib/b24.js            # REST-клиент: вызов методов, пагинация через batch, сборка отчёта
├── store/                # Redux: profile, filter (выбранный период), time (отчёт)
├── windows/              # content — раскладка дашборда
├── widgets/              # header, footer, contentHeader (карточки статистики),
│                         # chart (график активности), tasks (список задач), shares (доли по задачам)
├── entities/             # кнопка фильтра, карточки, bar (столбик графика),
│                         # task (строка задачи), share (строка легенды)
└── shared/               # список периодов, форматирование времени
```

Используемые методы REST: `profile`, `task.elapseditem.getlist` (записи учёта времени, с обходом пагинации через `batch`), `tasks.task.list` (названия задач). Агрегация считается на сервере — на клиент уезжает готовая сводка (`totalSeconds`, `avgSeconds`, `tasks`, `days`, для периода «Сегодня» ещё и `hours`).

Из сводки на клиенте строятся: карточки статистики (`contentHeader`), список задач со ссылками на Битрикс24, долей от самой объёмной задачи, числом записей и временем (`tasks`), наборная полоса долей — топ-5 задач плюс «Прочее» (`shares`) и график активности (`chart`). График подстраивается под выбранный период: «Сегодня» — по часам, «Неделя» и «Месяц» — по дням, «Год» — по месяцам; пиковый столбик выделяется цветом и выносится в заголовок.

Отчёт запрашивается один раз — `getTimeReport` диспатчит `contentHeader` при загрузке и смене фильтра, остальные виджеты только читают его из стора.
